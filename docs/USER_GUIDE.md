# 소리노트 사용자 안내서

소리노트는 녹음을 글로 바꾸고, 회의의 결정과 할 일을 정리하는 맥 앱입니다. 기록이 쌓이면 “이 일은 언제까지 하기로 했지?” 같은 질문도 할 수 있습니다. AI가 만든 문장은 틀릴 수 있으므로 중요한 내용은 원문과 원음을 함께 확인해 주세요.

## 처음 실행할 때

설치 파일을 열고 앱의 첫 실행 화면에서 **설치 시작**을 누르세요. 전용 Python과 음성·검색 엔진, 선택한 로컬 모델을 준비합니다. 기존 사용자는 **모델 및 환경 설정 → 공통 환경 → 자동 설치 / 복구…**를 열면 됩니다. [자동 설치 안내](INSTALLATION.md)에 자세한 절차를 정리했습니다. 소스 빌드는 [README](../README.md#소스에서-빌드하기)를 참고하세요.

“앱은 열리는데 요약이 안 된다”면 대부분 Ollama가 실행되지 않았거나 선택한 모델을 아직 받지 않은 상태입니다. **모델 및 환경 설정 → 공통 환경 → 저장하고 설치·연결 확인**에서 어느 부분이 준비되지 않았는지 확인할 수 있습니다. 이 검사는 서버 연결과 라이브러리 설치를 확인하며, 실제 모델 품질까지 평가하지는 않습니다.

### 화면 읽는 방법

| 위치 | 하는 일 |
| --- | --- |
| 왼쪽 | 새 녹음, 기록 목록, 제목·미리보기 검색, 파일 가져오기, 설정 |
| 가운데 | 선택한 자료의 요약·원문·화자, 원음 재생, 수정과 내보내기 |
| 오른쪽 | 전체 또는 선택 자료에 질문하고 검색된 근거 문단 확인 |
| 위쪽 진행 표시 | 현재 처리 단계와 취소 버튼 |

왼쪽 검색창은 제목과 원문 앞부분의 미리보기 검색입니다. 본문 전체에서 의미로 찾으려면 오른쪽 질문 패널을 사용하세요.

## 마이크와 시스템 오디오로 회의 녹음하기

1. **음성 설정**에서 마이크만 / 시스템 오디오만 / 둘 다를 선택해 저장한 뒤 **새 회의 녹음**을 누릅니다.
2. 선택한 소스에 맞게 마이크·시스템 오디오 캡처 권한을 허용합니다. 시스템 캡처는 허용 후 앱 재실행이 필요할 수 있습니다.
3. 녹음 표시줄에서 경과 시간과 마이크·시스템 입력 크기를 각각 확인합니다.
4. 잠시 쉬는 동안 **일시 정지**, 다시 시작할 때 **이어 녹음**을 누릅니다.
5. **녹음 완료**를 누르면 라이브러리에 저장됩니다.
6. 회의를 선택하고 **문자 변환**을 누릅니다.
7. 완료 후 **AI 요약 만들기**를 누릅니다.

**음성 설정**에서 마이크 장치를 고를 수 있습니다. **마이크 + 시스템 오디오**를 선택하면 내 말과 Teams 등에서 재생되는 상대방 소리를 함께 기록합니다. 시스템 오디오는 직접 캡처하므로 맥의 스피커 출력 음소거와 별도로 수집하도록 구현했습니다. Teams 자체가 재생을 중단한 소리는 기록할 수 없습니다.

처음 사용하는 맥에서는 [음성 설정 안내](AUDIO.md)의 권한·음소거 확인 절차를 먼저 진행하세요. 시스템 전체의 앱 소리가 포함되며 화면 영상은 저장하지 않습니다. 이어폰을 사용하면 스피커 소리가 마이크에 다시 들어오는 현상을 줄일 수 있습니다. 실시간 에코 제거는 적용하지 않았습니다.

녹음 중에는 AI 처리와 파일 가져오기를 제한해 작업이 겹치지 않게 합니다. 노트북을 닫거나 잠자기 상태로 전환하면 연속 녹음을 보장하지 못합니다. 중요한 녹음 전에는 짧게 시험하고, 저장 공간과 배터리를 확인해 주세요.

## 파일 가져오기

**녹음·문서 가져오기**에서 여러 파일을 선택할 수 있습니다.

- 음성: WAV, M4A, MP3 등을 가져온 뒤 문자 변환합니다. 원본 대신 앱 내부의 사본을 사용합니다.
- 텍스트: UTF-8 TXT와 Markdown을 바로 저장합니다.
- PDF: PDFKit이 추출할 수 있는 텍스트를 저장하며 `[3쪽]` 같은 쪽 표시를 추가합니다.

스캔 이미지뿐인 PDF는 OCR을 먼저 수행해야 합니다. 암호로 잠긴 PDF도 잠금을 해제한 파일을 준비하세요. Word, PPTX, HWP, 이미지 OCR은 현재 지원하지 않습니다. 여러 파일 중 하나에서 오류가 나면 앞서 저장된 파일은 유지되고, 남은 파일은 다시 가져와야 합니다.

직접 실행용 음성 파일은 2GB, 4시간 이내로 제한합니다. 음성 API 업로드는 25MB 이하입니다. 긴 회의는 적절한 길이로 나누어 주세요. 텍스트는 파일당 10MB, 저장 본문은 200만 글자 이내입니다.

## 화자 분리 사용하기

1. 설정의 **화자 분리** 단계에서 **문자 변환 후 화자 분리**를 켭니다.
2. **화자 수**는 모르면 자동(0), 정확히 알면 실제 인원으로 설정합니다.
3. Community-1 모델 페이지에서 이용 조건에 동의합니다.
4. 해당 계정의 Hugging Face 읽기 토큰을 입력하고 저장합니다.
5. **화자 분리 → 모델 다운로드 / 준비**를 실행합니다.
6. 녹음에서 문자 변환을 실행합니다.

기본 pyannote 화자 분리는 문자 변환을 마친 다음 CPU에서 실행됩니다. 회의 도중 즉시 이름이 나타나는 방식은 아닙니다. 완료되면 **원문·화자** 화면에 “화자 1”, “화자 2”처럼 표시합니다. 이름을 누르면 “지민”, “기획팀” 등으로 바꿀 수 있습니다.

같은 사람이 여러 화자로 나뉘거나 다른 사람이 같은 화자로 묶일 수 있습니다. 잡음, 짧은 발언, 비슷한 목소리, 여러 사람의 동시 발화가 원인입니다. 이름 변경은 같은 표시를 가진 모든 발언에 적용됩니다. 특정 한 문장만 화자를 바꾸는 전용 편집기는 아직 없습니다.

화자 이름을 바꾸면 본문과 검색 내용이 바뀌므로 이전 요약을 비웁니다. 다시 요약하면 새 이름을 반영합니다. 화자 분리에 실패해도 완료된 전사문은 유지하며, 화면에 별도 안내가 나타납니다.

## 원문 검토와 수정

**원문·화자**에서 시각을 누르면 해당 구간을 재생합니다. 요약에서 이상한 이름이나 숫자가 보이면 먼저 이 기능으로 실제 발언을 들어 보세요.

상단 **수정**에서는 제목과 본문을 바꿀 수 있습니다. 제목만 바꾸면 전사 구간과 요약은 유지됩니다. 본문을 직접 바꾸면 이전 구간의 시각·화자 정보가 더는 정확하다고 볼 수 없어 구간 정보를 비우며, 기존 AI 요약과 검색 색인도 비웁니다.

음성 문자 변환을 다시 실행하면 수동 수정과 화자 이름이 새 결과로 대체될 수 있습니다. 앱에서 덮어쓰기를 확인한 뒤 진행합니다. 필요한 내용은 먼저 Markdown으로 내보내세요.

## 내 자료에 질문하기

1. 검색 범위를 **모든 자료** 또는 **선택한 자료**로 정합니다.
2. “이번 회의에서 결정한 내용은?”처럼 질문합니다.
3. 처음에는 문서의 검색 색인을 만드는 시간이 필요합니다.
4. 답변의 `[1]`, `[2]` 표시와 아래 근거 문단을 함께 확인합니다.

검색된 문단은 최대 6개입니다. 모든 원문을 모델에 넣는 방식이 아니므로 검색에서 빠진 정보가 있을 수 있습니다. 자료에 없는 질문에는 확인하지 못했다고 답하도록 지시하지만, 모델이 그 지시를 완벽히 따르는 것은 아닙니다. 근거 번호는 모델이 생성하므로 번호와 내용이 실제로 맞는지 검토하세요. 출처 목록은 답변의 정확성을 자동 인증하는 표시가 아닙니다.

질문은 한 번씩 독립적으로 처리하며 채팅 이력을 저장하거나 이전 질문을 이어서 전달하지 않습니다. “그 사람은?”보다 “김지민의 담당 업무는?”처럼 대상을 명확하게 쓰면 좋습니다.

## 모델과 API Key 변경

왼쪽 아래 **모델 및 환경 설정** 버튼을 누르면 앱 안에 설정창이 열립니다. 왼쪽에서 **음성 인식 / 화자 분리 / 회의 요약 / 검색용 임베딩 / 질문 답변** 중 하나를 고르세요.

1. **실행 방식**에서 직접 실행, Ollama 또는 OpenAI 호환 API를 선택합니다. 단계마다 가능한 방식이 다릅니다.
2. **모델 이름 또는 로컬 폴더**를 수정합니다. 호환 API는 서버가 사용하는 정확한 모델 ID를 넣습니다.
3. API나 Ollama를 골랐다면 **서버 기본 주소**와 **API Key**도 수정할 수 있습니다.
4. **설정 저장**을 누릅니다. 다음 작업부터 사용하며, 앱을 다시 열어도 유지합니다.

검색용 임베딩의 기본값은 맥에서 직접 실행하는 **EmbeddingGemma 2**입니다. 처음에는 이 단계의 **모델 다운로드 / 준비**를 누르세요. 모델·주소·입력 형식을 바꾸면 다음 질문에서 검색 대상 자료의 색인을 다시 만듭니다. 같은 이름으로 서버 모델의 가중치만 바꾼 경우에는 **검색 색인 비우고 다음 검색에서 재생성**을 누릅니다.

- Ollama 기본 주소: `http://127.0.0.1:11434`
- OpenAI 호환 기본 주소 예시: `http://127.0.0.1:1234/v1`
- 인증이 없는 로컬 서버의 API Key는 비워 둡니다.
- 외부 서버를 쓰려면 **공통 환경 → 외부 서버로 음성·텍스트 전송 허용**을 켜고 HTTPS 주소를 사용합니다.

**기본값 복원**은 선택한 단계만 출고값으로 되돌립니다. 저장 버튼을 눌러야 적용합니다. 준비·점검 버튼은 먼저 현재 설정을 저장하므로, 저장하지 않은 모델과 다른 모델을 준비하는 혼동을 줄였습니다.

음성 API는 25MB 이하 파일을 지원합니다. `json` 전사에 시각이 없다면 본문만 저장하며 시각 이동과 후속 화자 분리는 사용할 수 없습니다. 화자 API는 `diarized_json`과 화자 구간을 반환해야 합니다. 연결 점검이 성공해도 서버가 이 기능을 지원하지 않을 수 있습니다. 자세한 규격은 [모델·API 안내](MODELS.md)를 보세요.

API Key를 지우고 저장하면 키체인에서도 해당 항목을 지웁니다. 앱의 키체인 접근을 거절하면 인증이 필요한 기능이 실패할 수 있습니다. 앱을 재빌드하면 임시 서명이 바뀌어 키체인 접근을 다시 물을 수 있습니다.

## 내보내기, 백업, 삭제

기록을 선택한 다음 위쪽 **내보내기**를 누르세요. macOS **파일 → 내보내기** 메뉴에도 같은 항목이 있습니다.

| 메뉴 | 저장되는 내용 |
| --- | --- |
| 녹음 + 전사문 함께 저장… | 고른 위치에 회의 제목의 새 폴더를 만들고 녹음 파일, `전사문.txt`, `회의록.md` 저장 |
| 녹음 파일만 저장… | 앱 내부 녹음의 사본. 녹음 직후, 문자 변환 전에도 사용 가능 |
| 전사문·원문만 저장… | 제목, 작성 시각, 현재 원문을 UTF-8 TXT로 저장. 가져온 문서에도 사용 가능 |
| 요약 포함 Markdown 저장… | 제목, 작성 시각, AI 요약, 현재 원문을 `.md`로 저장. 단축키 `⌘E` |

함께 저장하려면 녹음과 전사문이 모두 있어야 합니다. 아직 문자 변환 전이면 **녹음 파일만 저장…**을 쓰거나 먼저 문자 변환을 실행하세요. 요약은 필수가 아니며, 없으면 회의록에 아직 요약하지 않았다고 표시합니다. 녹음이 없는 문서에서는 녹음 저장 항목이 비활성화됩니다.

새로 녹음한 파일은 WAV이고, 가져온 M4A·MP3 등은 원래 형식 그대로 복사합니다. 묶음 안의 음성 파일 이름은 `녹음.wav`, `녹음.m4a`처럼 정해집니다. 원문에 있던 발언 시각과 수정한 화자 이름도 TXT와 Markdown에 그대로 들어갑니다. 직접 고친 본문이나 시각 없는 API 결과에는 없는 시간 정보를 임의로 붙이지 않습니다. 음성이나 전사문을 다시 생성하는 작업은 아닙니다.

같은 제목으로 묶음을 여러 번 저장하면 폴더 이름에 `(2)`, `(3)`을 붙입니다. 개별 파일의 이름이 겹치면 macOS 저장 창에서 교체 여부를 확인합니다. 복사 중 **취소**하면 미완성 결과를 지우고 원본과 기존 파일을 보존합니다. 앱의 데이터 폴더 안에는 내보낼 수 없으므로 문서 폴더나 다른 보관 위치를 고르세요.

내보낸 파일은 저장한 시점의 사본입니다. 이후 앱에서 전사문·화자 이름을 고치면 다시 내보내야 새 내용이 반영됩니다. 마이크와 시스템 오디오를 함께 녹음한 경우 하나로 합쳐진 녹음이 저장되며, 입력별 파일로 나누는 기능은 아닙니다.

- **백업**: 앱과 AI 작업을 모두 종료한 다음 설정의 데이터 폴더 전체를 복사합니다. API Key는 별도 키체인 항목이므로 폴더 복사에 포함되지 않습니다.
- **복원**: 앱을 종료한 상태에서 같은 데이터 폴더를 되돌립니다. 다른 맥에서는 Python과 모델을 다시 준비하고 키도 입력해야 합니다.
- **삭제**: 선택한 항목의 원문·요약·색인·앱 내부 녹음 사본을 지웁니다. 가져오기 전 원본과 사용자가 내보낸 파일은 삭제하지 않습니다.

파일 삭제는 디스크의 복구 불가능한 보안 삭제를 의미하지 않습니다. Time Machine이나 별도 백업에 남은 사본은 백업 정책에서 관리해야 합니다.

## 문제가 생겼을 때

| 증상 | 확인할 부분 |
| --- | --- |
| 마이크 접근이 안 됨 | 시스템 설정 → 개인정보 보호 및 보안 → 마이크에서 소리노트 허용 |
| Teams 소리가 안 들어옴 | 시스템 오디오 포함 모드, 화면 및 시스템 오디오 녹음 권한, Teams의 실제 재생 상태 확인 |
| 마이크 장치를 찾지 못함 | 음성 설정 → 장치 새로고침 후 연결된 마이크 선택 |
| 내 말이나 상대방 소리가 두 번 들림 | 이어폰 또는 맥 출력 음소거로 스피커 재수음 줄이기 |
| Python 실행 파일이 없다고 나옴 | 공통 환경의 자동 설치 / 복구 실행. 소스 개발 환경은 `.venv/bin/python` 절대 경로 확인 |
| 음성 엔진이 없다고 나옴 | `scripts/setup.sh` 실행 후 설정의 Python 경로 확인 |
| 모델 캐시 관련 오류 | 해당 단계의 모델 이름 확인 후 모델 다운로드 / 준비 실행 |
| 화자 분리만 실패 | 로컬 모델 준비·토큰 또는 화자 API의 diarized_json 지원, 앞 단계 전사의 구간 시각 확인 |
| 요약 서버 연결 실패 | Ollama 실행 여부, 주소와 포트, `ollama list`의 정확한 모델 이름 확인 |
| 로컬 전용 모드에서 주소 거절 | 루프백 주소인지 확인. 외부 연결이 목적이면 HTTPS와 전송 허용 사용 |
| 임베딩 차원 오류 | 검색 색인 다시 만들기 실행. 임베딩 전용 모델을 선택했는지 확인 |
| 변환이 느림 | 다른 모델 앱을 닫고, 더 작은 Whisper 모델이나 짧은 파일로 비교 |
| 취소 후에도 기록이 보임 | 취소 전에 완료된 전사문은 보존합니다. 목록에서 확인하세요. |
| 녹음 + 전사문 함께 저장이 비활성화됨 | 녹음이 있는 기록을 선택하고 문자 변환을 완료하세요. 녹음만 먼저 저장할 수 있습니다. |
| 파일 저장에 실패함 | 녹음 원본의 존재, 저장 공간, 폴더 쓰기 권한 확인. 앱 데이터 폴더 밖의 위치 선택 |
| 스캔 PDF를 읽지 못함 | 먼저 별도 OCR 도구로 텍스트가 있는 PDF로 변환 |

현재 버전은 원문이나 키가 로그에 남지 않도록 모델 라이브러리의 로그를 저장하지 않습니다. 오류를 보고할 때는 앱에 나온 메시지, macOS 버전, 선택한 모델 이름, 재현 순서만 공유하고 실제 회의 내용과 토큰은 빼 주세요.
